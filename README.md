# Автоматизация кассовых выгрузок

> [!CAUTION]
> **🔴 ВАЖНО: УЧЕБНЫЙ ПРОЕКТ.** Используются учебные, демонстрационные или обезличенные данные. Примеры, имена и контакты не следует воспринимать как реальные персональные данные клиентов. Результаты относятся к учебной выборке, а не к действующему бизнесу.

**Учебный кейс: регулярная обработка CSV от касс магазинов с проверками и загрузкой в PostgreSQL.**

**Стек:** Python · PostgreSQL · SQL · Windows Task Scheduler · CSV.

## Задача и решение

Нужно без ручного переноса собирать файлы продаж, проверять корректность данных и загружать их в базу по расписанию.

- Генерация CSV по расписанию и отдельный запуск загрузчика.
- Проверка формата, типов, скидок и обязательных полей до записи.
- Транзакционная загрузка каждого файла: ошибка не оставляет частично записанных продаж.
- SHA-256 и журнал файлов защищают от повторной загрузки; успешные файлы отправляются в архив.
- Логи и код завершения позволяют обнаружить ошибку запуска.

**Подтверждённый тест от 21.09.2026:** 3 CSV, 68 строк, 30 чеков на 34 046,30 ₽; повторная загрузка добавила **0 строк**. Это проверка учебного сценария, не коммерческие показатели.

```text
CSV от касс → валидация → PostgreSQL
                  |             |
              ошибки/лог    журнал файлов
                  |
             повторный запуск
```

## Состав проекта

- `generate.py` — генерация файлов `shop_num_cash_num.csv`.
- `load.py` — проверка CSV и загрузка в базу.
- `run_load.py` — запуск загрузчика, при необходимости запускает локальную PostgreSQL.
- `common.py` — чтение настроек и журнал.
- `config.json` — число магазинов, касс и чеков, настройки подключения.
- `sql/` — создание таблиц и запросы проверки.
- `data/` — папка входящих выгрузок, в репозитории есть примеры.
- `examples/` — копии примеров для повторной проверки.
- `scripts/register_tasks.ps1` — регистрация двух задач Windows.
- `img/` — подтверждения настройки и результата работы.

## Формат выгрузки

CSV в UTF-8 с BOM, разделитель — точка с запятой. Поля:
`doc_id;item;category;amount;price;discount`.

`price` — цена одной единицы до скидки. `discount` здесь трактуется как общая
скидка на строку чека. Сумма строки: `amount * price - discount`.
В одном чеке несколько товаров. Идентификатор содержит дату, номер магазина,
кассы и чека. Повторная генерация за тот же день с теми же настройками даёт
одинаковые данные.

По умолчанию создаются 3 выгрузки: 3 магазина, по одной кассе, по 10 чеков.
Настройка `cash_registers_per_shop` позволяет добавить несколько касс:
тогда файлов будет `shops * cash_registers_per_shop`.

## Запуск на новой машине

Нужны Windows, Python 3.10+ и PostgreSQL. Открыть PowerShell в папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

1. Установить и запустить PostgreSQL. В pgAdmin создать базу:

   ```sql
   CREATE DATABASE shop_sales;
   ```

2. В `config.json` указать свои host, port, dbname и user. В проверенном
   локальном варианте порт 55440; обычная установка PostgreSQL использует 5432.
3. Пароль в репозитории не хранится. Для ручного запуска передать его через
   `$env:PGPASSWORD = 'ваш пароль'`. Для задач Планировщика удобнее настроить
   стандартный файл `%APPDATA%\postgresql\pgpass.conf` пользователя, от имени
   которого запускаются задачи: `host:port:database:user:password`.
   Этот файл остаётся только на вашей машине. Служба PostgreSQL должна работать.
4. Проверить загрузку примеров:

   ```powershell
   .\.venv\Scripts\python.exe run_load.py
   ```

5. После загрузки `data/` освобождается, файлы перемещаются в `archive/`.
   Теперь можно проверить генератор и загрузчик:

   ```powershell
   .\.venv\Scripts\python.exe generate.py
   .\.venv\Scripts\python.exe run_load.py
   ```

Таблицы создаются автоматически из `sql/create_tables.sql`.
В воскресенье генератор заканчивается успешно без создания файлов.

## Расписание

В PowerShell из папки проекта выполнить:

```powershell
.\scripts\register_tasks.ps1
```

Если политика компьютера запрещает запуск скриптов, можно создать задачи
вручную в Планировщике Windows с такими же параметрами:

| Задача | Программа | Аргумент | Расписание |
|---|---|---|---|
| Simulative_Sales_Generate | Полный путь `.venv\Scripts\python.exe` | Полный путь `generate.py` в кавычках | Пн–Сб, 10:00 |
| Simulative_Sales_Load | Полный путь `.venv\Scripts\python.exe` | Полный путь `run_load.py` в кавычках | Ежедневно, 10:15 |

Рабочая папка обеих задач — папка проекта. Задачи запускаются от текущего
пользователя с обычными правами, **только когда пользователь вошёл в Windows**.
Компьютер должен быть включён. Пропущенный запуск выполняется при первой
возможности; одновременный запуск нескольких экземпляров запрещён.

Для проверки нажать «Выполнить» или:

```powershell
Start-ScheduledTask -TaskName Simulative_Sales_Generate
# Дождаться завершения генератора, затем:
Start-ScheduledTask -TaskName Simulative_Sales_Load
Get-ScheduledTaskInfo -TaskName Simulative_Sales_Load
```

`LastTaskResult = 0` означает успешное выполнение. Журналы — в папке `logs/`.
После проверки задачи остаются включёнными. Если расписание больше не нужно,
отключить обе задачи в Планировщике.

## Проверка данных и повторный запуск

Загрузчик принимает только имена вида `11_2.csv`. Посторонние файлы
игнорируются. Проверяются шесть столбцов, ID чека, непустые названия,
положительное количество, неотрицательные цены и допустимые скидки.
Денежные значения читаются через `Decimal` и сохраняются в `NUMERIC`.

Каждый файл загружается отдельной транзакцией. Ошибка отменяет загрузку
этого файла, сам файл остаётся в `data/`. Остальные файлы продолжают
обрабатываться. Если хотя бы один файл не загружен, код завершения — 1.

Таблица `sales` хранит строки чеков. `loaded_files` хранит имя и SHA-256
загруженного файла. Повторная загрузка не добавляет дубли. Если ранее
загруженная строка чека пришла с другими значениями, файл отклоняется.
После успешного commit файл переносится в архив. Если перенос прервался,
повторный запуск завершит его без повторной вставки продаж.

Генератор не перезаписывает необработанные CSV. Если прошлые файлы остались,
сначала нужно исправить причину ошибки и запустить загрузчик.
Генерация пропущенных исторических дней не предусмотрена.

## Проверка базы

Запросы приведены в `sql/check_sales.sql`. Например:

```sql
SELECT COUNT(*) FROM sales;
SELECT * FROM loaded_files ORDER BY loaded_at;
```

Для проверки использовалась отдельная переносимая PostgreSQL на localhost.
Её файлы и пароль находятся вне репозитория. `local-runtime.json` используется
только на проверочном компьютере; при обычной установке PostgreSQL он не нужен.
